# Architecture Decision Records

Create an ADR for a durable change to the learning environment or portfolio
story: a supported cluster type, workload architecture, registry, security
model, namespace policy, observability approach, or production environment.

Use `NNNN-short-title.md` and include:

1. **Context** — decision trigger and constraints.
2. **Decision** — what was chosen and by whom.
3. **Consequences** — benefits, trade-offs, and follow-up work.
4. **Status** — proposed, accepted, superseded, or deprecated.
5. **Links** — relevant issue, pull request, and validation evidence.

Do not use ADRs for routine tutorial steps. Link accepted ADRs from current
documentation when they change contributor or operational expectations.
